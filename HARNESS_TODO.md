## Items

- [ ] **T1**: commands/preview.go: `taufinity preview [map]` (default the current folder). Finds the data file: --data <csv>, else the only *.csv in the folder or in data/ (more than one: say which were found and ask for --data), else none (generated rows). Reads the CSV (comma or semicolon, decided from the header line; UTF-8 with optional BOM; header row = field names) into row objects; --row <n> picks one line, numbered as in the Product Layer (header is line 1, first data row is 2); without --row all rows (at most 50, then a Dutch message). Zips the folder with internal/archive.CreateZip, calls the endpoint, unpacks the answer into a fresh temp folder. Test TestBannerPreviewRequest with subtests sends_zip_and_rows, semicolon_csv, row_flag_picks_line, no_csv_sends_no_rows, two_csvs_asks_for_data.
- [ ] **T2**: Local server for the result: 127.0.0.1 only, a free port (--port to choose), serving the preview page at / and the prepared files at /rows/<i>/... Opens the browser at the page unless --no-open. The banner files on disk are never changed; when an entry HTML file is served, a small script is inserted right after <head> that (a) defines window.__taufinityReady when the file has <meta name="taufinity.ready" content="signal"> and reports to the page when it is called, and (b) nothing else. Test TestBannerPreviewServer with subtests serves_page_and_files, binds_localhost_only, ready_hook_only_with_meta_tag, files_on_disk_unchanged.
- [ ] **T3**: The preview page (one embedded HTML file, no external requests): the banner in an iframe at the report's width and height; a row picker with the row labels; an "Alle regels" overview showing every row side by side at banner size with its label (what a client approves); the field report (velden zonder waarde, kolommen die niets gebruikt, waarschuwingen); a badge with the ready signal ("klaar-signaal na N ms" or "geen klaar-signaal binnen 10 s") when the template uses it; a row error shown as an overlay with file, line and message instead of the banner. Test TestBannerPreviewPage with subtests has_row_picker, has_overview, has_field_report, has_ready_badge, has_error_overlay, each asserting the embedded page has that element by id.
- [ ] **T4**: Animation scrubber on the page: a time slider (0 to 10 s, or the template's duration when it exposes window.__taufinityDuration or a GSAP timeline duration) that, in the banner iframe, calls window.__taufinitySeek(t) when defined, else pauses window.gsap.globalTimeline and seeks it, else is hidden with the note "geen tijdlijn: als GIF of video wordt deze banner geweigerd". The same driver order as the render side. Test TestBannerPreviewPage subtest scrubber_driver_order checking the page script tries __taufinitySeek before gsap.
- [ ] **T5**: Watch mode, on by default (--no-watch to switch off): watch the template folder and the data file with fsnotify (add the dependency), ignore editor temp files (*.swp, *~, .DS_Store, 4913, .#*), debounce 250 ms after the last event, then refill (zip, call, unpack to a new temp folder, switch the server to it) and tell the page over server-sent events to reload, keeping the selected row and view. While a refill fails (network, 4xx), the last good banner stays with an error overlay, and the terminal prints one Dutch line per failure. Ctrl-C stops cleanly and removes the temp folders. Test TestBannerPreviewWatch with subtests burst_of_five_writes_refills_once, editor_temp_files_ignored, failed_refill_keeps_last_good, reload_event_sent.
- [ ] **T6**: `taufinity preview --init`: write voorbeeld.csv next to the template (semicolon separated, UTF-8): the header with every field from the report, and one row with the "voorbeeld" values the server generated (defaults and ‹naam› placeholders); fields ending in _url or _file are left empty, since the generated SVG placeholder is no use in a sheet. Refuses to overwrite an existing voorbeeld.csv without --force. Test TestBannerPreviewInit with subtests writes_header_and_row, refuses_overwrite.
- [ ] **T7**: Help and docs: `taufinity preview --help` explains the folder, the data file rules, --row, --init, watch mode and that filling happens on the server with the production code (so it is exactly what a render gets, minus the capture); README gets a "Banner templates bekijken" section with a 3-line example. Help of `taufinity template preview` names `taufinity preview` for banner templates and the other way round.
